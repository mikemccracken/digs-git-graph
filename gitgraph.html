Git graphs

git-graph draws the history of a git repository: branches as coloured lanes, commits as dots along them, and lines where branches leave and merge. Like Mermaid's gitGraph, you describe it as a list of events in the order they happen. It starts on main; each commit goes on the branch that's checked out, one column after the one before. 

(import (gitgraph))

(git-graph (pt 70 40)
  (commit "init")
  (commit "setup")
  (branch 'develop)
  (commit "login" #:tag "beta")
  (checkout 'main)
  (commit "hotfix" #:type 'highlight)
  (checkout 'develop)
  (commit "signup")
  (checkout 'main)
  (merge 'develop #:tag "v1.0")
  (commit "docs"))

The events are plain lists, (commit "init") is the same as '(commit "init"), so they can be quoted, built with map or kept in a variable. Lists of events are flattened, so a helper can return several. If your program defines its own merge or commit, which hides the library's, quote the events instead, as with '(commit "a") below. 

(import (gitgraph))

(define (feature name . messages)
  (list (branch name)
        (map commit messages)
        (checkout 'main)
        (merge name)))

(git-graph (pt 30 30)
  '(commit "a")
  (feature 'search "index" "query")
  (feature 'export "csv")
  #:direction 'down #:gap 36)

git-graph

(git-graph origin event … #:gap 50 #:lane-gap 50 #:direction 'right|'down #:main "main" #:colors (list color …))

Draws the events as one group, with the first commit at the point origin. #:gap is the distance from one commit to the next and #:lane-gap the distance between lanes. With #:direction 'right (the default) time runs left to right, branch names sit at the start of their lanes, labels go below commits and tags above. With 'down it runs top to bottom, like git log --graph, and labels line up to the right of every lane. #:main names the starting branch. Each new branch takes the next colour from #:colors, starting again when they run out. 

(import (gitgraph))

(git-graph (pt 90 30)
  (commit) (commit)
  (branch "release/2.0")
  (commit "rc1" #:tag "2.0-rc1")
  (checkout "trunk")
  (commit)
  #:main "trunk" #:gap 40 #:lane-gap 44
  #:colors (list "#495057" "#c2255c"))

On the canvas: dragging any part moves the whole graph by changing the numbers in origin. Double-click a commit label, tag or branch name written as a string to edit it. The Git graph tool (H) drags out a small graph to start from.

commit

(commit label #:tag tag #:type 'normal|'highlight|'reverse)

A commit on the checked-out branch. The label is optional. #:tag adds a tag next to it; #:type 'highlight draws it as a square and 'reverse crosses it out, for a revert.

branch

(branch name #:color color)

Starts a branch at the checked-out branch's last commit, on a new lane, and checks it out. Names are symbols ('develop) or strings ("release/2.0", for names with a slash). #:color overrides its colour from #:colors.

checkout

(checkout name)

Switches to a branch, so the next commit goes on it.

merge

(merge name label #:tag tag #:type type)

A merge commit on the checked-out branch, joined to the last commit of branch name, drawn as a ring. It takes the same label and options as commit. The merged branch stays where it was, so it can carry on and be merged again. 

(import (gitgraph))

(git-graph (pt 80 30)
  (commit)
  (branch 'develop) (commit) (commit)
  (checkout 'main) (merge 'develop "merge 1")
  (checkout 'develop) (commit "revert" #:type 'reverse)
  (checkout 'main) (merge 'develop "merge 2" #:tag "v2"))
